# ADR 0007 — Secure tenant operations console

Status: implements the approved EAAP-008 specification; pending independent review. EAAP-000 through EAAP-007 are accepted. Builds on [ADRs 0001–0006](../README.md); backend contracts and trust boundaries remain unchanged.

## Structure and dependencies

Preserve React 19.3.1, strict TypeScript 6.0.3, Vite 8.3.8, the existing four Compose services and existing CI. Feature modules cover dashboard, agents, knowledge, executions, approvals and admissions. `app/Console` owns the responsive navigation shell; `auth` owns login, tenant verification and the in-memory session; `api` owns decoded contracts, request handling and fixed tenant endpoint methods; `components` owns reusable controls and cancellable request hooks. Navigation is in application state, with no sensitive parameters or tokens in URLs. Reload returns to login rather than restoring a session or history. No new runtime dependency, router, global state framework, authentication service or business endpoint is added.

Two pinned test-only dependencies, `@testing-library/react` 16.3.3 and `jsdom` 31.0.1, allow Vitest to exercise browser DOM interactions instead of only static markup. They are not imported by the application. Package-lock pins transitive resolutions. Optional Chromium verification uses temporary Playwright tooling outside the repository, without another service or a mandatory browser download in CI.

## Authentication and tenant lifecycle

Login uses only POST `/api/v1/auth/login`. The token lives in a private in-memory `MemorySession`, copied into private request scopes while active. No cookies, localStorage, sessionStorage, URL tokens, refresh flow, analytics or credential logging exist. Password fields are cleared on successful login and unmounted on navigation. Expiry is bounded by the returned lifetime and the accepted 900-second maximum; a timer clears the session and private UI. Any authenticated HTTP401 disposes all scopes, cancels requests, removes tenant state and returns to login with an expiry message. Login401 instead gives the non-enumerating invalid-credentials message.

Tenant selection accepts an existing syntactically valid UUID and verifies GET `/tenants/{id}/context`. The returned immutable user UUID and database-derived role determine UI affordances, not authorization. There is no discovery, signup, membership administration or role header. Every API remains subject to Spring's live membership/RLS enforcement. A stale browser role can show an action subsequently denied403 by Spring; the response is displayed without bypass or optimistic business mutation.

Switching tenant first closes all old request scopes and unmounts the entire tenant console, then requests new membership confirmation. Cancellation and closed-scope guards reject late responses. Hook cleanup aborts feature requests and guards state commits. Pagination hides prior-page data while a new page loads. Logout clears the session, tenant context, provider-cost acknowledgment and all feature state. Page reload requires a fresh login.

## Same-origin API routing

Both Vite development and existing Vite preview proxy only paths matching `^/api/v1/` to a fixed Spring target. Host development uses `http://127.0.0.1:8080`; the existing web container sets server-only `EAAP_WEB_CONTAINER=1`, selecting `http://control-plane:8080`. No user-supplied target, arbitrary destination, Python route, wildcard CORS or new routing service is introduced. Browser requests always use relative `/api/v1/...` paths. Existing public VITE API build arguments/configuration are removed; no build-time secret or internal credential is needed.

The proxy streams JSON and multipart bodies and forwards Authorization and X-Request-ID/status responses. Upstream cookies are stripped and API responses receive no-store. Proxy failure returns static JSON502, without logging private request/response content. Proxy/request deadlines are bounded to accommodate existing embedding plus synchronous execution limits. The web image includes its Vite configuration for preview; it remains the existing non-root development preview service, not a production hosting choice. Preview sets no-store, nosniff, no-referrer and a same-origin CSP without external script, network or framing permissions. Local Vite HMR retains its development behavior. See Vite's [server proxy](https://vite.dev/config/server-options#server-proxy) and [preview proxy](https://vite.dev/config/preview-options#preview-proxy) contracts.

## HTTP and sensitive data

The lightweight client sends Bearer only to fixed relative API paths, with `credentials: omit`, `redirect: error`, `cache: no-store` and no-referrer. JSON and multipart are separate, allowing the browser to set multipart boundaries. Every request has an AbortController and a 120-second complete-response deadline; response bytes are capped at8MiB before runtime DTO decoding. Contract decoders validate object fields, UUIDs, enums, nullable metadata, numeric values, dates and bounded arrays from actual Java DTOs. Malformed responses become sanitized502 rather than unsafe assumptions.

Errors expose static status-specific text, a validated request UUID and, for run errors, a validated run UUID. Raw response messages/codes/private payloads never become error toasts or logs. 403/404/409/413/429/provider failures are explicit; mutation/timeouts are never replayed automatically. Known stored failure categories use a fixed safe allowlist. Unknown model usage is unavailable, not zero. Untrusted configuration, filenames, passages, questions, answers, rationales and reasons use ordinary React text; there is no HTML injection or link construction from customer text.

## UI and approval semantics

Desktop sidebar and horizontally scrollable compact navigation use semantic buttons, visible focus, labeled inputs, status text, tables, bounded pagination, loading/error/empty states and native modal dialogs with Escape handling and focus restoration. UI permission checks improve usability; only Spring authorizes. Archived configurations are read-only. Dashboard labels first-page counts explicitly when hasNext is true; no fabricated totals or analytics are introduced.

Knowledge uploads show PDF/TXT,2MiB,25-page and existing server limits. Server parsing/type/quota validation remains authoritative. Document list/detail refreshes are sequential,3seconds, at most60 automatic refreshes per mounted view; only PENDING/PROCESSING triggers polling. Terminal status, navigation, logout, tenant switch and unmount stop it. A manual refresh allows another explicit check. Search shows real passage, filename, document UUID, nullable page and cosine similarity, never confidence.

Q&A is single-turn, displays only the submitted question and one current durable result. First execution in the session requires explicit cost/configuration acknowledgment; AI proposal generation always requires a separate paid-call confirmation. Neither is called on page load. Errors with runId support explicit read-only retrieval; a user may enter another own run UUID. A provider may be unavailable. Timeouts do not prove no billable work occurred.

Proposal detail renders the exact immutable tool/version, creator, arguments, rationale, digest and current state. Self-approval is disabled for the creator; MEMBER never sees manager actions. A different current manager confirms the displayed payload and submits its reviewed digest. Approval refreshes state and never dispatches execution. Rejection requires a nonblank reason<=500 and is terminal. An APPROVED proposal exposes a separate confirmation identifying the tool, actual arguments and creation of one real OPEN task. Controls and synchronous action guards block duplicate submissions while pending. Successful result shows taskId and links to read-only tasks. There is no frontend idempotency protocol or optimistic task creation; Spring's immutable success replay/transaction/unique constraint remains authoritative. A409 requires renewed review; no silent reapproval or automatic retry is attempted.

## Verification and limitations

Deterministic mocked HTTP tests are test-only and cover auth/tenant/cancellation, role controls, agent writes/conflicts, upload validation/polling, citations, model failures/unknown usage, exact digest, self-approval denial, deliberate decisions, separate execution and duplicate-click protection. Existing Java/Python suites remain unchanged and continue to enforce the actual security boundary. Real browser verification, actual counts, image/HTTP evidence and screenshots are recorded in [EAAP-008 delivery evidence](../../tasks/EAAP-008.md).

This is a development-ready console, not production hosting or a production security claim. In-memory tokens can still be stolen by a compromised same-origin script/browser; reload intentionally loses navigation/session state. There is no refresh, multi-tab synchronization, tenant discovery, run listing, conversation memory, task editing, approval UI bypass or new tool. Concurrent draft edits keep accepted last-writer semantics. Full knowledge association discovery beyond the API's first100 remains unavailable. Browser input maxlength counts UTF-16 units and may be stricter for supplementary Unicode than server code-point limits. Hosted model quality/paid account access is not verified with a live call. Production TLS, identity, rate limits, dependency/image hardening, content retention, workload isolation and external tool delivery remain separate architectural work.
